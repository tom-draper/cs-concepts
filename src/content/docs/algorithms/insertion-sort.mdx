Insertion sort is how most people sort a hand of cards. Hold the sorted cards on the left, pick up the next card, and slide it leftward past every card that is bigger. Repeat until there are no cards left to pick up.

## Watch it run

The bright bars are the sorted section so far; the faded ones have not been looked at yet. Things to notice:

- Each new value moves left only as far as it needs to, then stops. Nothing to the left of that point is examined.
- Try **Sorted**. Each value is compared once with its neighbour and stays put: 7 comparisons, no writes. This is the best case.
- Try **Reversed**. Every value has to travel all the way to the front. This is the worst case.

## The code

The demo swaps neighbours so the movement is easy to follow. The standard implementation is a little more efficient: lift the new value out, shift the larger values one place right, and drop it into the gap.

```python
def insertion_sort(a):
    for i in range(1, len(a)):
        key = a[i]
        j = i - 1
        while j >= 0 and a[j] > key:
            a[j + 1] = a[j]      # shift right
            j -= 1
        a[j + 1] = key           # drop into the gap
```

## The cost depends on the disorder

The work done for each element is the number of larger elements before it. In the worst case, reversed input, that is everything: 1 + 2 + … + (n − 1), which is **O(n²)**.

But if every element is already close to where it belongs, each one moves only a few places and the total is close to **O(n)**. This property is called being **adaptive**, and insertion sort is the best example of it.

## Why real sorting libraries use it

For large arrays, O(n²) loses badly to [merge sort](/algorithms/merge-sort/) and [quicksort](/algorithms/quicksort/). For **small** arrays it wins. It has almost no overhead: no recursion, no extra memory, and one tight loop over neighbouring memory that processors execute very efficiently.

So production sorts are hybrids. They use an O(n log n) algorithm to break the problem down, and switch to insertion sort once the pieces are small, typically a few dozen elements.

- **Timsort** (Python, Java for objects) uses insertion sort to build its initial sorted runs.
- **Introsort** and **pdqsort** (C++, Rust, Go) finish small partitions with it.

Insertion sort is not a toy. It is the last step of the sort you actually call.

## Insertion or bubble or selection?

All three are O(n²) and in place. They are not equally good.

| | Bubble | Selection | Insertion |
| --- | --- | --- | --- |
| Comparisons on sorted input | n | n²/2 | n |
| Writes | many | fewest | moderate |
| Stable | yes | no | yes |
| Use in practice | none | when writes are costly | small or nearly sorted arrays |

## Key takeaways

- Insertion sort grows a sorted section by sliding each new item left into place.
- It is O(n²) in general, and O(n) on input that is already nearly sorted.
- It is stable, in place, and can sort data as it arrives.
- It is the fastest choice for small arrays, which is why hybrid library sorts use it for their final step.
