Many problems ask about **contiguous runs** of an array or string: the largest sum of any 7 consecutive days, the longest stretch without a repeated character, the shortest run that adds up to at least some total.

The direct approach examines every run separately. The sliding window technique notices that neighbouring runs overlap almost completely. Moving the window one step along changes only two elements: one enters and one leaves. So update the answer for those two, and reuse everything else.

## Fixed-size windows

**Problem.** Find the largest sum of any 3 consecutive values.

Adding up each group of three from scratch does three additions per position. Instead, keep a running sum. To slide the window along, add the value that enters and subtract the value that leaves.

export const data = [2, 1, 5, 1, 3, 2, 6, 1];
export const k = 3;
export const sums = data.slice(0, data.length - k + 1).map((_, i) => data.slice(i, i + k).reduce((a, b) => a + b, 0));
export const best = Math.max(...sums);

<Player>
  {sums.map((sum, i) => (
    <Frame
      caption={
        (i === 0
          ? `The first window: ${data.slice(0, k).join(' + ')} = ${sum}.`
          : `Slide right: the previous sum ${sums[i - 1]}, minus ${data[i - 1]} leaving, plus ${data[i + k - 1]} entering, is ${sum}.`) +
        ` Best so far: ${Math.max(...sums.slice(0, i + 1))}.`
      }
    >
      <ArrayViz
        values={data}
        highlight={sum === best ? [] : [i, i + 1, i + 2]}
        alt={sum === best ? [i, i + 1, i + 2] : []}
        dim={data.map((_, n) => n).filter((n) => n < i || n >= i + k)}
      />
    </Frame>
  ))}
</Player>

```python
def max_window_sum(values, k):
    window = sum(values[:k])
    best = window
    for i in range(k, len(values)):
        window += values[i] - values[i - k]     # one in, one out
        best = max(best, window)
    return best
```

The saving grows with the window. For a window of 1,000 over a million values, recomputing costs a billion additions. Sliding costs two million.

| Approach | Work per position | Total |
| --- | --- | --- |
| Recompute each window | O(k) | O(n × k) |
| Slide | O(1) | O(n) |

## Variable-size windows

The more powerful form lets the window **grow and shrink**. It has two ends, `left` and `right`, which are a pair of [pointers](/algorithms/two-pointers/) that only ever move forward.

- Move `right` forward to **grow** the window, taking in a new element.
- While the window breaks the rule you care about, move `left` forward to **shrink** it.

**Problem.** Find the length of the longest stretch of a string with no repeated character.

```python
def longest_unique_run(text):
    seen = set()
    left = 0
    best = 0
    for right, ch in enumerate(text):
        while ch in seen:               # the new character is a repeat:
            seen.remove(text[left])     # shrink from the left until it is not
            left += 1
        seen.add(ch)
        best = max(best, right - left + 1)
    return best
```

For `abcabcbb` the answer is 3, for `abc`.

### Why it is linear

There is a `while` inside a `for`, which looks quadratic. It is not. `left` only ever moves forward, so across the *entire* run it advances at most n times in total. Each character is added to the window once and removed at most once. That is O(n) overall.

This kind of argument, counting total movement instead of work per step, is [amortized analysis](/foundations/amortized-analysis/).

### The general shape

```python
left = 0
for right in range(len(items)):
    add(items[right])                 # grow
    while window_is_invalid():
        remove(items[left])           # shrink
        left += 1
    update_answer(left, right)
```

Variations change only what "valid" means and what is recorded.

| Problem | Window state | Shrink while |
| --- | --- | --- |
| Longest run with no repeats | a set of characters | the new character is already present |
| Longest run with at most k distinct values | a count per value | more than k distinct |
| Shortest run with sum at least S | a running sum | the sum is still at least S (to find a shorter one) |
| Smallest run containing all of some letters | a count per letter | every required letter is still covered |

## What the window needs to remember

The technique works when the window's summary can be updated in O(1) as elements enter and leave.

| Summary | Add | Remove | Structure |
| --- | --- | --- | --- |
| Sum, count, average | easy | easy | a number |
| Which values are present | easy | easy | a [set](/data-structures/sets/) or [hash table](/data-structures/hash-tables/) of counts |
| **Maximum or minimum** | easy | **hard** | a [deque](/data-structures/deques/#sliding-window-maximum) |

Maximum is the awkward one. When the largest value leaves the window, you need to know the next largest. A plain variable cannot tell you. The standard solution keeps a deque of candidates in decreasing order, and it is described on the deques page.

## When it does not apply

A variable window relies on a **one-directional** effect: growing the window can only push it towards breaking the rule, and shrinking can only push it back.

"Shortest run with sum at least S" works when all the values are **positive**, because then adding an element always increases the sum and removing one always decreases it. Allow negative numbers and that breaks: shrinking the window might *increase* the sum, and the technique no longer knows which end to move. That version needs a different approach, using prefix sums.

## Where it shows up

- **Rolling statistics**: moving averages on stock prices, sensor readings, request rates.
- **Rate limiting**: "no more than 100 requests in any 60 seconds" is a window over time.
- **Networking**: TCP sends data within a window of unacknowledged bytes that slides forward as acknowledgements arrive. See [TCP](/networking/tcp/).
- **String search**: [Rabin-Karp](/algorithms/rabin-karp/) slides a window along the text, updating a hash instead of a sum.
- **Compression**: LZ77, used in ZIP and PNG, looks for repeats within a sliding window of recent data.
- **Stream processing**: aggregating events over the last N minutes.

## Key takeaways

- A sliding window handles contiguous runs by updating a result as one element enters and one leaves.
- A fixed window turns O(n × k) into O(n).
- A variable window grows on the right and shrinks on the left, and is O(n) because each end only moves forward.
- It needs a summary that is cheap to update, and a rule that growing and shrinking affect in opposite directions.
- For a sliding maximum or minimum, use a deque.
